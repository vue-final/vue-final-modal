---

Both modal components follow the [WAI-ARIA dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). They handle the focus and the keyboard. You give each modal a name, label its buttons and pick where the focus starts.

## What the modals do

| | `<VueFinalModal>`{lang=ts} | `<VueFinalDialog>`{lang=ts} |
| --- | --- | --- |
| Role | `role="dialog"`{lang=html} and `aria-modal="true"`{lang=html} on the `.vfm`{lang=ts} element | A native `<dialog>`{lang=html} opened with `showModal()`{lang=ts} |
| Focus when it opens | The first element with `autofocus`{lang=html} in the content, or else the content itself | The first element with `autofocus`{lang=html}, or else the first one `Tab`{lang=ts} reaches, or else the dialog |
| Focus while it is open | Trapped in the modal: `Tab`{lang=ts} and `Shift+Tab`{lang=ts} cycle through its elements | Kept out of the page, which the browser makes inert |
| `Esc`{lang=ts} | Closes it, see [escToClose](/api/components/vue-final-modal#esctoclose) | Closes it, see [closedby](/api/components/vue-final-dialog#closedby-optional) |
| Focus when it closes | Back to the element that opened it, level by level for nested modals | Back to the element that had it before, by the browser |
| The page behind | Hidden from screen readers by `aria-modal`{lang=html} | Inert and hidden from screen readers |
| Name | Linked from the [`titleId`{lang=ts} slot prop](#a-name), with a warning in development when it is missing | Same |

## What you add

### A name

Screen readers announce a dialog by its name when the focus moves in. Without one, they say only "dialog". Render the title with the `titleId`{lang=ts} of the default slot, and the main message, if there is one, with its `descriptionId`{lang=ts}:

```vue
<VueFinalModal v-slot="{ close, titleId, descriptionId }">
  <h2 :id="titleId">Delete the file?</h2>
  <p :id="descriptionId">It cannot be restored.</p>
  <button @click="close()">Cancel</button>
</VueFinalModal>
```

The modal gets `aria-labelledby`{lang=ts} and `aria-describedby`{lang=ts} pointing at them once they are rendered. A modal with no visible title takes an `aria-label`{lang=ts} attr instead. An `aria-labelledby`{lang=ts} or `aria-describedby`{lang=ts} attr you pass wins over the slot props.

A component passed to `useModal()`{lang=ts} as a slot does not receive the slot props. Put the title in a [modal component of your own](/api/components/vue-final-modal#wrapping-vuefinalmodal) instead, which renders `<VueFinalModal>`{lang=ts} with `v-slot`{lang=ts}.

In development, a modal that opens without a name logs a warning, and so does an `alertdialog`{lang=ts} without a description.

### Labelled buttons

A close button that shows only an icon or `×`{lang=html} needs a name, or screen readers read out the character:

```html
<button aria-label="Close" @click="close()">×</button>
```

### Where the focus starts

Put `autofocus`{lang=html} on the element the user most likely wants first:

- In a form, the first field.
- In a confirmation that deletes or discards something, the button that does not, such as Cancel.
- In a modal with long or structured content, nothing: the focus then lands on the content, at its start.

`<VueFinalModal>`{lang=ts} also takes a [focusTrap](/api/components/vue-final-modal#focustrap) `initialFocus`{lang=ts}, such as `{ initialFocus: '#email' }`{lang=ts}, which wins over `autofocus`{lang=html}.

## Alert dialogs

A modal that interrupts to ask for a decision, such as deleting a file, is an `alertdialog`{lang=ts}: screen readers announce it more urgently. Pass the role as an attr, describe the decision with `descriptionId`{lang=ts}, and start the focus on the least destructive button:

```vue
<VueFinalModal
  v-slot="{ close, titleId, descriptionId }"
  role="alertdialog"
  :click-to-close="false"
>
  <h2 :id="titleId">Delete the file?</h2>
  <p :id="descriptionId">It cannot be restored.</p>
  <button autofocus @click="close()">Cancel</button>
  <button @click="remove()">Delete</button>
</VueFinalModal>
```

`Esc`{lang=ts} still closes it, as the [alert dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/) expects. To make a choice mandatory, also set [escToClose](/api/components/vue-final-modal#esctoclose) to `false`{lang=ts}, or `closedby="none"`{lang=html} on a `<VueFinalDialog>`{lang=ts}.

## Non-modal dialogs

With [`background: 'interactive'`{lang=ts}](/api/components/vue-final-modal#background), the page behind a `<VueFinalModal>`{lang=ts} stays usable, so the modal is a non-modal dialog: it drops `aria-modal`{lang=html}, and the focus moves into it when it opens and back when it closes but is free to reach the page in between. Pass [focusTrap](/api/components/vue-final-modal#focustrap) options to trap it anyway.

## Which component to use

`<VueFinalDialog>`{lang=ts} leaves the page behind to the browser, which makes it inert: nothing there can be reached by `Tab`{lang=ts}, by a click or by the reading cursor of a screen reader. `<VueFinalModal>`{lang=ts} traps the focus and hides the page with `aria-modal`{lang=html}, which screen readers support unevenly. When its [limits](/api/components/vue-final-dialog#when-to-use-it) do not get in the way, `<VueFinalDialog>`{lang=ts} is the more robust choice.

Whichever you use, try your modals with the keyboard alone and with a screen reader, such as VoiceOver on macOS and iOS or NVDA on Windows.
