## Migrating from 4.x to 5.0

vue-final-modal 5.0 rebuilds `useModal()`{lang=ts} on top of [vue-use-template](https://github.com/hunterliu1003/vue-use-template), while keeping the public API compatible with 4.x.

For most apps **no code change is needed**: `createVfm()`{lang=ts}, `<ModalsContainer />`{lang=ts}, `useModal()`{lang=ts} with `open()`{lang=ts} / `close()`{lang=ts}, `useVfm()`{lang=ts}, `useModalSlot()`{lang=ts} and `$vfm`{lang=ts} all keep working as before. The `<VueFinalModal>`{lang=ts} component itself (props, events, slots) stays the same.

What can need a change: installing the peer dependencies, a few removed advanced APIs that leaked the old internals, and some behaviors described below.

### Install the peer dependencies

4.x installed `@vueuse/core`, `@vueuse/integrations` and `focus-trap` as its own dependencies. 5.0 lists them only as peer dependencies, together with the new [vue-use-template](https://github.com/hunterliu1003/vue-use-template), and needs Vue 3.3 or later instead of 3.2. npm and pnpm install peer dependencies for you. With Yarn, add them yourself:

```bash
yarn add vue-final-modal vue-use-template @vueuse/core @vueuse/integrations focus-trap
```

### Removed `vfm.dynamicModals`

The dynamic modals created by `useModal()`{lang=ts} are no longer exposed as an array on the vfm instance. Control each modal with the `open()`{lang=ts} / `close()`{lang=ts} functions returned by `useModal()`{lang=ts}, or close everything with `useVfm().closeAll()`{lang=ts}.

### Removed `useModal().options` and `patchOptions()`

`useModal()`{lang=ts} no longer returns the internal reactive `options`{lang=ts} object, and `patchOptions()`{lang=ts} is gone. Pass a `ref`{lang=ts}, `computed`{lang=ts} or getter function as `attrs`{lang=ts} instead. The modal stays in sync with it:

So this:

```ts
const modal = useModal({
  component: ModalConfirm,
  attrs: { title: 'Hello World!' },
})

modal.patchOptions({ attrs: { title: 'Hello Vue!' } })
```

Will be re-written as this:

```ts
const title = ref('Hello World!')

const { open, close } = useModal({
  component: ModalConfirm,
  attrs: () => ({ title: title.value }),
})

title.value = 'Hello Vue!'
```

Swapping the `component`{lang=ts} of an existing modal is no longer supported: create a separate modal with `useModal()`{lang=ts} instead.

### Removed `getModalExposed()`

`getModalExposed()`{lang=ts} operated on component internal instances and is gone. `useVfm()`{lang=ts} keeps exposing `get(modalId)`{lang=ts}, `open(modalId)`{lang=ts}, `close(modalId)`{lang=ts}, `toggle(modalId)`{lang=ts} and `closeAll()`{lang=ts}.

### `focusTrap` options are merged over the defaults

In 4.x, the options you passed to [focusTrap](/api/components/vue-final-modal#focustrap) replaced its default `{ allowOutsideClick: true }`{lang=ts}. In 5.0 they are merged over `{ allowOutsideClick: true, escapeDeactivates: false }`{lang=ts}, so outside clicks keep reaching [clickToClose](/api/components/vue-final-modal#clicktoclose) unless you set `allowOutsideClick`{lang=ts} yourself. The `esc`{lang=ts} key no longer deactivates the focus trap on its own: [escToClose](/api/components/vue-final-modal#esctoclose) handles it, so with `escToClose: false`{lang=ts} the focus stays trapped in the modal.

### Scroll locking moved to `@hunterliu/scroll-lock`

5.0 locks the scroll with [@hunterliu/scroll-lock](https://github.com/hunterliu1003/scroll-lock), which replaces the copy of body-scroll-lock that 4.x carried. [lockScroll](/api/components/vue-final-modal#lockscroll) and [reserveScrollBarGap](/api/components/vue-final-modal#reservescrollbargap) keep their names and defaults. Two things you may notice:

- A modal rendered inside a scroll container, for example with `teleportTo: false`{lang=ts}, locks that container as well as the page.
- A scroll container keeps the room of its scrollbar with `scrollbar-gutter: stable`{lang=ts} where the browser supports it. The page still gets the scrollbar's width as `padding-right`{lang=ts}.

### `open()` outside any app context on the server is ignored

On the server, `open()`{lang=ts} of a modal created outside a component (for example at module level or in a store) and called outside any app context is now ignored with a warning. 4.x opened it in the last created vfm, which can belong to another request when requests run concurrently. Call `useModal()`{lang=ts} in `setup()`{lang=ts} to open a modal during a server render. In the browser nothing changes.

### A modal opened outside a component opens once the app has mounted

A modal opened outside a component before the app renders, for example from a Nuxt plugin or a route middleware, is no longer part of the server HTML: the server skips that `open()`{lang=ts} with a warning and resolves it right away. In the browser the modal opens once the app has mounted, with its enter transition, so hydration never meets a modal the server did not render, whether the code runs on both sides or only in the browser. 4.x rendered such a modal on the server, and one opened only in the browser before the app mounted caused a hydration mismatch. Do not await that `open()`{lang=ts} before the app mounts: it settles once the modal has opened. To show a modal on the first paint, open it while a component sets up, for example in `app.vue` or in a page.

A server that polyfills `window` cannot be told apart from a browser by looking at `window`, so it has to say it is a server: call `markServer()`{lang=ts} once, before it renders. The Nuxt module does this for you.

```ts [server entry]
import { markServer } from 'vue-final-modal'

markServer()
```

### The Nuxt module ships inside the package

`@vue-final-modal/nuxt` is no longer published. The module is part of `vue-final-modal` as `vue-final-modal/nuxt`, so remove the old package and change the module name:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['vue-final-modal/nuxt'],
})
```

The module now also auto-imports the components and composables. If another module or your own `composables/` directory auto-imports one of the same names, such as a `useModal()`{lang=ts} of its own, set `vueFinalModal: { autoImports: false }`{lang=ts} and keep importing from `vue-final-modal`. See [Setup](/get-started/guide/setup#nuxt).

### New capabilities

Not breaking, but worth knowing:

- `attrs`{lang=ts}, `props`{lang=ts} and `emits`{lang=ts} of `useModal()`{lang=ts} accept a `ref`{lang=ts}, `computed`{lang=ts} or getter for reactive updates.
- A modal opened while a component sets up during the server render is part of the server HTML, with its z-index, and hydrates already open: no enter transition plays on the first paint.
- `defineTemplate()`{lang=ts} is a type helper for slot content with props and events (an alternative to `useModalSlot()`{lang=ts}).
- `createModalsProvider()`{lang=ts} creates an [isolated instance](/api/components/modals-container#advanced-isolated-instances) with its own `<ModalsProvider>`{lang=ts}, `useModal()`{lang=ts} and `useVfm()`{lang=ts} for advanced scenarios such as micro frontends.
- The promises of `open()`{lang=ts} and `close()`{lang=ts}, from `useModal()`{lang=ts} and from `useVfm()`{lang=ts}, always settle: with `'opened'`{lang=ts} or `'closed'`{lang=ts} once the transition has finished, or with a message when the modal never got there, for example when `beforeOpen` called `stop()`{lang=ts} or the modal was destroyed first. See [what they resolve with](/api/composables/use-modal#what-open-and-close-resolve-with).
- `require('vue-final-modal')`{lang=ts} loads a CommonJS build with its own `.d.cts`{lang=ts} types instead of the UMD build. The UMD build is still there for [CDNs](/get-started/guide/setup#from-a-cdn).

### Summary

| 4.x                                  | 5.0                                                          |
| ------------------------------------ | ------------------------------------------------------------ |
| `createVfm()` + `app.use(vfm)`       | Unchanged                                                     |
| `<ModalsContainer />`                | Unchanged                                                     |
| `useModal().open()` / `.close()`     | Unchanged                                                     |
| `defaultModelValue` / `keepAlive`    | Unchanged                                                     |
| `useModalSlot()`                     | Unchanged (`defineTemplate()` is the new alternative)         |
| `this.$vfm` / `useVfm()`             | Unchanged                                                     |
| `vfm.dynamicModals`                  | Removed, use the functions returned by `useModal()`           |
| `useModal().options`                 | Removed, use reactive `attrs`                                 |
| `patchOptions()`                     | Removed, use reactive `attrs` (`ref` / `computed` / getter)   |
| `getModalExposed()`                  | Removed, use [useVfm()](/api/composables/use-vfm)             |
| Server `open()` outside any app context | Ignored with a warning                                     |
| `open()` from a Nuxt plugin or route middleware | Opens in the browser once the app has mounted      |
| `modules: ['@vue-final-modal/nuxt']` | `modules: ['vue-final-modal/nuxt']`, no extra package         |
| Nuxt: import the components and composables | Auto-imported, `vueFinalModal: { autoImports: false }` to opt out |
| `@vueuse/*` and `focus-trap` as dependencies, Vue 3.2+ | Peer dependencies with `vue-use-template` (add them yourself with Yarn), Vue 3.3+ |
| `focusTrap` options replace `{ allowOutsideClick: true }` | Merged over `{ allowOutsideClick: true, escapeDeactivates: false }` |
| Vendored body-scroll-lock for the page | `@hunterliu/scroll-lock`, also locks the scroll container a modal is rendered in |

## Migrating from 3.x to 4.0

Please check the [vue-final-modal 4.x documentation](https://v4.vue-final-modal.org) for the 3.x to 4.0 migration guide, then migrate to 5.0 from there.
