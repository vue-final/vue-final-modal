title: 'useModal()'
description: 'A composable function to define a dynamic modal.'
---

With `useModal()`{lang=ts}, that means you don't have to add the modal to your Vue template and you don't have to use [v-model](/get-started/guide/setup#v-model) or [modalId](/get-started/guide/setup#modalid) to open or close the modal. You can simply use it to create a dynamic modal everywhere and control it programmatically.

## Prerequisite

Dynamic modals are rendered by [\<ModalsContainer>](/api/components/modals-container), so make sure it is included in your app once:

```vue [App.vue]
<script setup lang="ts">
import { ModalsContainer } from 'vue-final-modal'
</script>

<template>
  <!-- Your app -->
  <ModalsContainer />
</template>
```

## Usage

### Passing Props and Events

`useModal(options)`{lang=ts} takes the options that describe the modal component, and returns `open()`{lang=ts} and `close()`{lang=ts} functions to control it.

```ts
import { VueFinalModal, useModal } from 'vue-final-modal'

const { open, close } = useModal({
  // Open the modal right after it was created, the default value is `false`.
  defaultModelValue: false,
  // Keep the modal mounted after it was closed, the default value is `false`.
  keepAlive: false,
  // The modal component. Use `<VueFinalModal>` or `<VueFinalDialog>` directly, or your own styled modal component.
  component: VueFinalModal,
  attrs: {
    // Bind props to the modal component (VueFinalModal in this case).
    clickToClose: true,
    escToClose: true,
    // Bind events to the modal component (VueFinalModal in this case).
    // Any custom events can be listened for when prefixed with "on", e.g. "onEventName".
    onBeforeOpen() { /* on before open */ },
    onOpened() { /* on opened */ },
    onBeforeClose() { /* on before close */ },
    onClosed() { /* on closed */ },
  },
})

// Open the modal
open().then(() => { /* Do something after modal opened */ })
// Close the modal
close().then(() => { /* Do something after modal closed */ })
```

Each required prop of `component`{lang=ts} has to be given, in `attrs`{lang=ts} or in `props`{lang=ts}: `props`{lang=ts} only has to give the required props that `attrs`{lang=ts} leaves out, and a required prop given nowhere is a type error.

### Reactive attrs

`attrs`{lang=ts} can also be a `ref`{lang=ts}, `computed`{lang=ts} or a getter function. The modal will keep in sync with it, so you can update the modal's props dynamically without any extra API:

```ts
import { ref } from 'vue'
import { VueFinalModal, useModal } from 'vue-final-modal'

const title = ref('Hello World!')

const { open, close } = useModal({
  component: VueFinalModal,
  attrs: () => ({
    title: title.value,
  }),
})

// Updating the ref updates the opened modal as well
title.value = 'Hello Vue!'
```

A single prop can be a `ref`{lang=ts} too, in `attrs`{lang=ts} and in the `attrs`{lang=ts} of a slot template:

```ts
const title = ref('Hello World!')

const { open, close } = useModal({
  component: VueFinalModal,
  attrs: { title },
})
```

### Keeping the modal alive

By default the modal is unmounted when it closes and mounted again by the next `open()`{lang=ts}. With `keepAlive: true`{lang=ts} it stays mounted after `close()`{lang=ts}, hidden with `display: none`{lang=ts}, so its state survives. `destroy()`{lang=ts} unmounts it when you are done with it. A kept-alive modal is not destroyed when the component that created it unmounts, so call `destroy()`{lang=ts} yourself. See the [Modal Keep Alive](/use-cases/modal-keep-alive) example.

```ts
import { useModal } from 'vue-final-modal'
import ModalDraft from './ModalDraft.vue'

const { open, close, destroy } = useModal({
  keepAlive: true,
  component: ModalDraft,
})

await open()
await close() // Still mounted, the draft inside is kept
await open() // The draft is still there
destroy() // Unmounted, the next open() starts from a fresh component
```

### Passing Slots

#### with `String`


```ts
import { VueFinalModal, useModal } from 'vue-final-modal'

const { open, close } = useModal({
  component: VueFinalModal,
  attrs: { ... },
  slots: {
    default: '<p>The content of the modal</p>'
  }
})
```

::warning
Security Note: https://vuejs.org/api/built-in-directives.html#v-html
Dynamically rendering arbitrary HTML on your website can be very dangerous because it can easily lead to XSS attacks. Only use v-html on trusted content and never on user-provided content.
::

#### with `Component`


```ts
import { VueFinalModal, useModal } from 'vue-final-modal'
// ModalContent is the component you want to put into the modal content
import ModalContent from './ModalContent.vue'


const { open, close } = useModal({
  component: VueFinalModal,
  attrs: { ... },
  slots: {
    // You can import your own component as a slot and put it to `slots.default` without binding props and events.
    default: ModalContent
  }
})
```

A component in `slots`{lang=ts} does not receive the slot props of the modal, such as `close`{lang=ts} and `titleId`{lang=ts}: it reads them with [useModalContext()](/api/composables/use-modal-context).

#### with `Component`, `Props` and `Events`

```ts
import { VueFinalModal, defineTemplate, useModal } from 'vue-final-modal'
// ModalContent is the component you want to put into the modal content
import ModalContent from './ModalContent.vue'

const { open, close } = useModal({
  component: VueFinalModal,
  attrs: { ... },
  slots: {
    default: defineTemplate({
      component: ModalContent,
      attrs: {
        // Bind ModalContent props
        title: 'Hello world!'
        // Bind ModalContent events
        onConfirm() {  }
      }
    })
  }
})
```

#### with a `ref` or `computed`

Any of the slots above can also be a `ref`{lang=ts} or `computed`{lang=ts}. The modal keeps in sync with it:

```ts
import { computed, ref } from 'vue'
import { VueFinalModal, useModal } from 'vue-final-modal'

const message = ref('Hello World!')

const { open, close } = useModal({
  component: VueFinalModal,
  slots: {
    default: computed(() => `<p>${message.value}</p>`),
  },
})

// Updating the ref updates the opened modal as well
message.value = 'Hello Vue!'
```

::note
A template in `slots`{lang=ts} is only type-checked when it is wrapped in `defineTemplate()`{lang=ts}: without it, its attrs, props and listeners are taken as they are.

`defineTemplate()` is a function that provides better DX for type checking. It just returns the same object you passed in. `useModalSlot()`{lang=ts} from 4.x does the same and keeps working, and `defineModal()`{lang=ts} is the same kind of helper for the template of a whole modal: its component, attrs and slots.
::

## What `open()` and `close()` resolve with

`open()`{lang=ts} resolves with `'opened'`{lang=ts} once the enter transition has finished, and `close()`{lang=ts} resolves with `'closed'`{lang=ts} once the leave transition has finished. They never stay pending: when the modal does not get there, they resolve with why, so compare the result to know what happened. The results are typed as `ModalOpenResult`{lang=ts} and `ModalCloseResult`{lang=ts}.

```ts
const { open } = useModal({ component: ModalConfirm })

if (await open() === 'opened') {
  // The modal is opened and its enter transition has finished
}
```

| Result | When |
| --- | --- |
| `'opened'`{lang=ts}, `'closed'`{lang=ts} | The enter or the leave transition has finished. |
| `'already-opened'`{lang=ts}, `'already-closed'`{lang=ts} | The modal was already opened, or already closed. |
| `'stopped'`{lang=ts} | `beforeOpen`{lang=ts} or `beforeClose`{lang=ts} called `event.stop()`{lang=ts}. |
| `'toggled-again'`{lang=ts} | The modal was toggled again before it finished, for example closed by the `esc`{lang=ts} key while it was still opening. |
| `'destroyed'`{lang=ts} | The modal was destroyed before it finished, by `destroy()`{lang=ts} or because the component that created it unmounted. |
| `'skipped-on-server'`{lang=ts} | `open()`{lang=ts} only: the server skipped a modal created or opened outside a component, see [Server-side rendering](#server-side-rendering). |

An `open()`{lang=ts} called while the modal is opening settles with that opening, and a `close()`{lang=ts} called while it is closing settles with that closing. A `close()`{lang=ts} called while the modal is still opening waits until it has opened, then closes it: `open()`{lang=ts} resolves with `'opened'`{lang=ts} and `close()`{lang=ts} with `'closed'`{lang=ts}.

[\<VueFinalDialog>](/api/components/vue-final-dialog), the components built on [useModalLifecycle()](/api/composables/use-modal-lifecycle) and the functions of [useVfm()](/api/composables/use-vfm) resolve with the same results.

## Status

`status`{lang=ts} is a read-only ref of where the modal is: `'closed'`{lang=ts}, `'opening'`{lang=ts}, `'opened'`{lang=ts} or `'closing'`{lang=ts}. `'opening'`{lang=ts} and `'closing'`{lang=ts} last until the transitions have finished.

```vue
<script setup lang="ts">
const { open, status } = useModal({ component: ModalConfirm })
</script>

<template>
  <button :disabled="status !== 'closed'" @click="open()">
    Open
  </button>
</template>
```

`vfm.get(modalId)?.value.status`{lang=ts} and the `status`{lang=ts} of [useModalLifecycle()](/api/composables/use-modal-lifecycle) give the same for a modal component.

## Server-side rendering

A modal opened while a component sets up, with `defaultModelValue: true`{lang=ts} or an `open()`{lang=ts} called in `setup()`{lang=ts}, is part of the server HTML and hydrates already open. On the server its `open()`{lang=ts} resolves with `'opened'`{lang=ts} right away.

A modal created or opened outside a component is skipped on the server with a warning, and its `open()`{lang=ts} resolves with `'skipped-on-server'`{lang=ts} right away there. That covers a modal opened from a Nuxt plugin or a route middleware, and a modal a module creates once and opens in `setup()`{lang=ts}: every request would share its open state. In the browser it opens once the app has mounted. Do not await that `open()`{lang=ts} before the app mounts: it settles once the modal has opened.

After an `await` in `setup()`{lang=ts}, it depends on where the component sits. A component around `<ModalsContainer>`{lang=ts}, such as `app.vue`, finishes its setup before the container renders, so its modal is still part of the server HTML, as long as it calls `useModal()`{lang=ts} before the `await` or uses `<script setup>`{lang=ts}. The server does not wait for a component next to the container, such as a page: its modal shows in the browser only, after hydration.
