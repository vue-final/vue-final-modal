---
title: 'useModalLifecycle()'
description: 'Build your own modal component that useModal() can open and await.'
---

`useModal()`{lang=ts} renders any `component`{lang=ts} you give it. It passes the component a `modelValue`{lang=ts}, and settles `open()`{lang=ts} and `close()`{lang=ts} on the events the component emits once it has opened or closed. `useModalLifecycle()`{lang=ts} emits them for you, so your component only shows and hides itself. [\<VueFinalDialog>](/api/components/vue-final-dialog) is built on it.

## Usage

Declare `modalComponentProps`{lang=ts} and `ModalComponentEmits`{lang=ts}, and give `useModalLifecycle()`{lang=ts} an `open`{lang=ts} and a `close`{lang=ts} hook. A hook that returns a promise holds `opened`{lang=ts} or `closed`{lang=ts} back until it settles, for example until a transition ends:

```vue [MyDialog.vue]
<script setup lang="ts">
import type { ModalComponentEmits } from 'vue-final-modal'
import { ref } from 'vue'
import { modalComponentProps, useModalLifecycle } from 'vue-final-modal'

const props = defineProps(modalComponentProps)
const emit = defineEmits<ModalComponentEmits>()

const dialog = ref<HTMLDialogElement>()
const { isOpen, reportClosed } = useModalLifecycle(props, emit, {
  open: () => dialog.value!.showModal(),
  close: () => dialog.value!.close(),
})

function onClose() {
  if (!dialog.value!.open)
    reportClosed()
}
</script>

<template>
  <dialog ref="dialog" @cancel.prevent="isOpen = false" @close="onClose">
    <slot />
  </dialog>
</template>
```

```ts
const { open } = useModal({ component: MyDialog })

await open() // 'opened'
```

The hooks run once the component has mounted and rendered the new state. The browser may close the dialog on `Esc` although `cancel`{lang=ts} was prevented, which `onClose`{lang=ts} reports. It skips the `close`{lang=ts} event of a dialog opened again before the event fired.

## Return value

- `isOpen`{lang=ts}: whether the modal is open. Set it to open or close the modal from inside, for example from a close button: `beforeOpen`{lang=ts} or `beforeClose`{lang=ts} is emitted first, and `update:modelValue`{lang=ts} after.
- `reportClosed()`{lang=ts}: reports a modal that already closed by itself, such as a dialog a `<form method="dialog">`{lang=html} closed, so `beforeClose`{lang=ts} is not asked.
- `toggle(show?)`{lang=ts}: opens or closes the modal and resolves once it has, like [useVfm().toggle()](/api/composables/use-vfm). Called while the modal is heading there, it settles with that change.
- `status`{lang=ts}: a read-only ref of where the modal is, `'closed'`{lang=ts}, `'opening'`{lang=ts}, `'opened'`{lang=ts} or `'closing'`{lang=ts}, like the [status of useModal()](/api/composables/use-modal#status).

## What it guarantees

Your component's `open()`{lang=ts} and `close()`{lang=ts} resolve with [the same results](/api/composables/use-modal#what-open-and-close-resolve-with) as those of `<VueFinalModal>`{lang=ts}:

- `'opened'`{lang=ts} and `'closed'`{lang=ts} once the hook settled,
- `'stopped'`{lang=ts} when `beforeOpen`{lang=ts} or `beforeClose`{lang=ts} called `event.stop()`{lang=ts}, which also writes the previous value back to `v-model`,
- `'toggled-again'`{lang=ts} when the modal was toggled again before its hook settled: the late hook does not emit `opened`{lang=ts} or `closed`{lang=ts},
- `'destroyed'`{lang=ts} when the component unmounted before its hook settled.

## Events

`ModalComponentEmits`{lang=ts} lists the events `useModalLifecycle()`{lang=ts} emits: `update:modelValue`{lang=ts}, `beforeOpen`{lang=ts}, `opened`{lang=ts}, `beforeClose`{lang=ts} and `closed`{lang=ts}, plus the internal `_opened`{lang=ts}, `_closed`{lang=ts}, `_stopped`{lang=ts} and `_status`{lang=ts} that `useModal()`{lang=ts} listens to. In the Options API, use `emits: modalComponentEmits`{lang=ts}.

Declare them only on the component that shows the modal. A wrapper around `<VueFinalDialog>`{lang=ts} or `<VueFinalModal>`{lang=ts} that declares them swallows the internal listeners of `useModal()`{lang=ts}: let them fall through to the inner component instead.
