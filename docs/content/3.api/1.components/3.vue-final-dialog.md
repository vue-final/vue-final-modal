title: '<VueFinalDialog>'

---

`<VueFinalDialog>`{lang=ts} renders a native [`<dialog>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/dialog) and opens it with `showModal()`{lang=ts}. It plugs into [useModal()](/api/composables/use-modal), `v-model` and [useVfm()](/api/composables/use-vfm) like `<VueFinalModal>`{lang=ts}, and its `open()`{lang=ts} and `close()`{lang=ts} resolve with [the same results](/api/composables/use-modal#what-open-and-close-resolve-with).

The browser does the rest: the dialog sits in the top layer, so it needs no `z-index`, the page behind it is inert, `Esc` closes it, the focus moves into it on open and back on close. `<VueFinalDialog>`{lang=ts} ships no styles and no transitions of its own.

## Template structure

```html [VueFinalDialog.vue]
<template>
  <dialog :closedby="closedby">
    <slot :close="close" />
  </dialog>
</template>
```

Every attr you pass, such as `class`{lang=ts} or `aria-labelledby`{lang=ts}, falls through to the `<dialog>`.

## Usage

### With `useModal()`

```ts
import { useModal, VueFinalDialog } from 'vue-final-modal'

const { open, close } = useModal({
  component: VueFinalDialog,
  attrs: {
    class: 'my-dialog',
    closedby: 'any',
    onClosed() { /* on closed */ },
  },
  slots: { default: '<p>Hello from a native dialog</p>' },
})

await open() // 'opened'
```

### With `v-model`

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { VueFinalDialog } from 'vue-final-modal'

const show = ref(false)
</script>

<template>
  <button @click="show = true">
    Open
  </button>
  <VueFinalDialog v-model="show" class="my-dialog">
    <template #default="{ close }">
      <p>Hello from a native dialog</p>
      <button @click="close">
        Close
      </button>
    </template>
  </VueFinalDialog>
</template>
```

`Esc`, a click outside with `closedby="any"`{lang=ts} and a `<form method="dialog">`{lang=html} all close the dialog in the browser, and `<VueFinalDialog>`{lang=ts} writes `false` back to `v-model`.

### Transitions

Animate the dialog and its `::backdrop` with CSS. `opened`{lang=ts} and `closed`{lang=ts}, and so `open()`{lang=ts} and `close()`{lang=ts}, wait for the transitions and animations that run on the `<dialog>` itself and on its `::backdrop`, so a dialog opened by `useModal()`{lang=ts} is unmounted only after it faded out:

```css
.my-dialog {
  opacity: 1;
  transition: opacity .3s, overlay .3s allow-discrete, display .3s allow-discrete;
}
.my-dialog:not([open]) {
  opacity: 0;
}
@starting-style {
  .my-dialog[open] {
    opacity: 0;
  }
}
```

The animations of the content inside the dialog, and animations that never end, are not waited for.

## Props

### modelValue (optional)

Display the dialog or not.
  - Type:
    - JS: `Boolean`{lang=ts}
    - TS: `PropType<boolean>`{lang=ts}
  - Default: `undefined`{lang=ts}

### modalId (optional)

An uniq value to open and close the dialog with [useVfm()](/api/composables/use-vfm): `open(modalId)`{lang=ts}, `close(modalId)`{lang=ts}, `toggle(modalId)`{lang=ts} and `closeAll()`{lang=ts}.
  - Type:
    - JS: `[String, Number, Symbol]`{lang=ts}
    - TS: `PropType<ModalId>`{lang=ts}
  - Default: `undefined`{lang=ts}

### modal

Open the dialog with `showModal()`{lang=ts}. Set it to `false`{lang=ts} to open it with `show()`{lang=ts} instead: a non-modal dialog leaves the page interactive and is not in the top layer. It applies the next time the dialog opens.
  - Type:
    - JS: `Boolean`{lang=ts}
    - TS: `PropType<boolean>`{lang=ts}
  - Default: `true`{lang=ts}

### closedby (optional)

The native [`closedby`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/dialog#closedby) attribute: `'any'`{lang=ts} also closes the dialog on a click outside, `'none'`{lang=ts} keeps it open on `Esc`. Browsers that do not support it ignore it.
  - Type:
    - JS: `String`{lang=ts}
    - TS: `PropType<'any' | 'closerequest' | 'none'>`{lang=ts}
  - Default: `undefined`{lang=ts}

### lockScroll

Lock the scroll of the page while the dialog is open, with [@hunterliu/scroll-lock](https://hunterliu.tw/scroll-lock/). A modal dialog makes the page inert but does not stop it from scrolling. The page keeps the room of its scrollbar, so its content does not shift.
  - Type:
    - JS: `Boolean`{lang=ts}
    - TS: `PropType<boolean>`{lang=ts}
  - Default: `false`{lang=ts}

## Events

- `(e: 'beforeOpen', event: { stop: () => void }): void`{lang=ts}: Emits before the dialog opens.
  - `event.stop()` keeps it closed. The pending `open()`{lang=ts} then resolves with a message instead of `'opened'`{lang=ts}.
- `(e: 'opened'): void`{lang=ts}: Emits after the dialog opened and its transitions ended.
- `(e: 'beforeClose', event: { stop: () => void }): void`{lang=ts}: Emits before the dialog closes, also on `Esc` and on a click outside with `closedby="any"`{lang=ts}.
  - `event.stop()` keeps it open. The pending `close()`{lang=ts} then resolves with a message instead of `'closed'`{lang=ts}.
  - On `Esc` the browser lets the page keep the dialog open only after the user interacted with the page, and not for a second `Esc` in a row: then the dialog closes anyway.
  - A `<form method="dialog">`{lang=html} closes the dialog without asking, so `beforeClose`{lang=ts} is not emitted for it.
- `(e: 'closed'): void`{lang=ts}: Emits after the dialog closed and its transitions ended. A dialog opened by `useModal()`{lang=ts} is unmounted right after, unless it has `keepAlive`{lang=ts}.

- `(e: 'cancel', event: Event): void`{lang=ts}: The native `cancel` event of a close request, such as `Esc`. `event.preventDefault()`{lang=ts} keeps the dialog open without asking `beforeClose`{lang=ts}, within the same limits as above.
- `(e: 'close', event: Event): void`{lang=ts}: The native `close` event, fired once the `<dialog>` closed and before its transitions end.

Read the [`returnValue`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/returnValue) of a `<form method="dialog">`{lang=html} in `close`{lang=ts}:

```ts
useModal({
  component: VueFinalDialog,
  attrs: {
    onClose: (event: Event) => console.log((event.target as HTMLDialogElement).returnValue),
  },
})
```

## Slots

- The `default`{lang=ts} slot renders the content of the dialog. Its `close`{lang=ts} closes the dialog.

## Server-side rendering

The dialog is rendered closed on the server, with its content, and opens once the app has hydrated: an open `<dialog>` in the server HTML could not become a modal one. `open()`{lang=ts} resolves on the server right away, like for `<VueFinalModal>`{lang=ts}.

## Next to `<VueFinalModal>`

A modal dialog makes everything outside the top layer inert. A `<VueFinalModal>`{lang=ts} opened while a `<VueFinalDialog>`{lang=ts} is open shows behind the dialog and cannot be used, whatever its `z-index`. Open another `<VueFinalDialog>`{lang=ts} on top of a dialog instead: the browser stacks them in the order they opened.

## Your own dialog component

`<VueFinalDialog>`{lang=ts} is built on [useModalLifecycle()](/api/composables/use-modal-lifecycle), which you can use to build your own modal component that `useModal()`{lang=ts} can open and await.
